# Melodia Backend VPS Deployment Guide

This guide explains how to install, run, and maintain the Melodia backend as an always-on system service on your Linux VPS (Ubuntu/Debian).

---

## 1. Before You Start

Make sure you have:
1. **A domain or subdomain** pointing to your VPS IP address (e.g., `music-api.yourdomain.com`).
2. **DNS A record configured:** Create an **A record** in your DNS provider for `music-api.yourdomain.com` pointing to your VPS public IPv4 address. Wait until `nslookup music-api.yourdomain.com` returns your VPS IP address.
3. **SSH access** to your VPS with `sudo` privileges.
4. **Project folder on the VPS:** Clone or move the repository to `/var/www/music-app`.
5. **Python virtual environment:**
   ```bash
   cd /var/www/music-app/backend
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt
   ```

---

## 2. Dry-Run First (Safe Inspection)

Before making any changes to your server, run the installer in dry-run mode. It will print the exact execution plan without modifying any files or services:

```bash
cd /var/www/music-app
sudo bash deploy/install.sh --domain music-api.yourdomain.com --email you@example.com
```

Read the plan carefully. Notice that:
- It checks that port `8610` is free.
- It detects Nginx and Certbot.
- It prepares the dedicated `melodia` system user.
- It keeps other projects on the server untouched.

---

## 3. Apply the Installation

When the plan looks good, run with `--apply` and `--create-env`:

```bash
sudo bash deploy/install.sh --domain music-api.yourdomain.com --email you@example.com --create-env --apply
```

This will:
1. Create the unprivileged `melodia` system user (no login shell).
2. Set ownership on `data/`, `backups/`, `.tmp/`, `.home/`, `.cache/` (mode 700).
3. Generate a production `backend/.env` with a strong random JWT secret.
4. Install and enable the `melodia-backend.service` and `melodia-health.timer`.
5. Configure Nginx rate-limiting and reverse proxying for audio streaming.
6. Run `nginx -t` and reload Nginx.
7. Request an HTTPS certificate using Certbot.

---

## 4. Create Your Owner Account

Because public registration is closed in production, create your personal account using the CLI tool:

```bash
cd /var/www/music-app/backend
sudo -u melodia .venv/bin/python -m app.tools.create_user --email you@example.com
```

You will be prompted to enter and confirm your password interactively. Use a strong password generated by your password manager.

---

## 5. Verify the Server

Verify that your backend is running and healthy:

```bash
# 1. Check health endpoint from your computer or server:
curl https://music-api.yourdomain.com/health

# 2. Check service status:
sudo systemctl status melodia-backend

# 3. View live logs:
sudo journalctl -u melodia-backend -f
```

---

## 6. Configure Your Flutter App

Open `client/dart_defines.json` on your computer (this file is gitignored and stays private on your machine):

```json
{
  "API_URL": "https://music-api.yourdomain.com",
  "APP_NAME": "Melodia",
  "LOCAL_EMAIL": "you@example.com",
  "LOCAL_PASSWORD": "YourStrongPasswordHere"
}
```

Now build or run your client app:
```powershell
cd client
flutter run -d windows --dart-define-from-file=dart_defines.json
```

## 7. Prove It Restarts (Resilience Test)

1. **Kill test:** Kill the backend process abruptly:
   ```bash
   sudo systemctl kill -s SIGKILL melodia-backend
   ```
2. Wait 3 seconds, then check status:
   ```bash
   sudo systemctl status melodia-backend
   ```
   Systemd automatically restarts the process immediately (`Restart=always`).
3. **Reboot test:** Reboot the VPS:
   ```bash
   sudo reboot
   ```
   After reboot, verify the service is running automatically without manual intervention.

## 8. Maintenance & Updates

### Deploying New Code
To update your server after pushing commits to GitHub:
```bash
cd /var/www/music-app
sudo bash deploy/deploy.sh --apply
```
This automatically backs up the database, pulls latest code, runs database migrations, restarts the backend, and polls `/ready`. If `/ready` fails, it rolls back automatically to the previous commit.

### When yt-dlp Breaks ("Song Won't Play")
YouTube periodically updates its video streaming algorithms. To update yt-dlp safely:
```bash
cd /var/www/music-app
sudo bash deploy/update_ytdlp.sh --apply
```
This updates yt-dlp, tests stream resolution with `python -m app.tools.selftest_stream`, and only restarts the service if the test passes. If stream resolution fails, it rolls back automatically.

### Database Backups
To take a manual SQLite snapshot:
```bash
cd /var/www/music-app/backend
sudo -u melodia .venv/bin/python -m app.tools.backup
```
Backups are saved to `/var/www/music-app/backups/music-YYYYMMDD-HHMMSS.db` with mode 600.

## 9. Security & Bandwidth Notes

- **Loopback binding:** The backend binds strictly to `127.0.0.1:8610`. It is never exposed directly to the public internet; only Nginx terminates external TLS traffic.
- **Registration disabled:** `ALLOW_REGISTRATION=false` in `.env` prevents strangers from creating accounts.
- **Bandwidth protection:** The app enforces daily per-user (1500 MB) and global monthly (1500 GB) bandwidth limits to protect shared VPS quotas.
- **Sandboxed systemd:** The service runs with `NoNewPrivileges=true`, `ProtectSystem=strict`, `ProtectHome=true`, and restricted write paths.

## 10. Troubleshooting

| Symptom | Probable Cause | Action |
|---|---|---|
| **502 Bad Gateway from Nginx** | Backend service stopped or starting | Check `systemctl status melodia-backend` and `journalctl -u melodia-backend -n 50`. |
| **401 Unauthorized in App** | Password or email mismatch | Verify credentials or reset password using `python -m app.tools.create_user --email you@example.com --reset-password`. |
| **Certbot TLS Failed** | DNS record not yet propagated | Ensure `nslookup music-api.yourdomain.com` returns the VPS IP, then run `sudo certbot --nginx -d music-api.yourdomain.com`. |
| **Port 8610 Taken** | Another process is using port 8610 | `install.sh` automatically chooses the next free port. Re-run `install.sh` to update port. |
| **Search works but song won't play** | Upstream yt-dlp is outdated | Run `sudo bash deploy/update_ytdlp.sh --apply`. |

## 11. Rollback & Uninstall

### Reverting a Bad Deploy
```bash
cd /var/www/music-app
git checkout <previous_commit_hash>
sudo systemctl restart melodia-backend
```

### Complete Uninstall
To safely remove all Melodia systemd units and Nginx configs:
```bash
cd /var/www/music-app
# Dry run:
sudo bash deploy/uninstall.sh
# Apply:
sudo bash deploy/uninstall.sh --apply
```
Your project code and database (`data/music.db`) remain untouched.

---

## 12. Manual Steps for the Owner

These steps cannot be automated safely without your VPS environment access:
1. **DNS A Record:** Create the subdomain A record at your registrar or Cloudflare pointing to your VPS IP.
2. **Firewall:** Ensure ports 80 and 443 are open in your VPS firewall (`sudo ufw allow 80/tcp` and `sudo ufw allow 443/tcp`).
3. **Optional Weekly yt-dlp Timer:** You can schedule a weekly Sunday update by adding a cron job:
   ```bash
   # In sudo crontab -e:
   0 4 * * 0 cd /var/www/music-app && bash deploy/update_ytdlp.sh --apply >> /var/log/melodia-update.log 2>&1
   ```
4. **Optional Daily Backup Cron:**
   ```bash
   # In sudo crontab -e:
   0 3 * * * cd /var/www/music-app/backend && sudo -u melodia .venv/bin/python -m app.tools.backup >> /var/log/melodia-backup.log 2>&1
   ```
